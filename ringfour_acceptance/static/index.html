Set up Local virtual AP

These tests need two real accounts with separate test organizations and separate robots. Saving different organization IDs alone is not enough.

  1. Keep A and B’s test organizations private from each other. A’s account must not be a member of B’s test organization, and B’s account must not be a member of A’s. Use dedicated test organizations with only the intended account as Developer or Owner. If both accounts already share an organization, choose an isolated test organization and enroll its test robot there.
  2. Enroll one independent robot in each organization. In Stacks, start their virtual stacks. Each role needs its own robot UUID and enrolled Daemon. Check that each stack’s Robot ID matches the robot selected for that organization, and leave both robots idle.
  3. Connect an account runner for each login. The panel connects cdr automatically. In Setup → Connect account, copy a fresh worker command into ring1’s own shell, using that account’s CLI login. Leave the shell running. The command connects the account to this panel; it does not launch a robot or start tests. Pairing codes expire after five minutes and work once.
  4. Save the environment. Select Local virtual AP below, then open Configure IDs and runners. Set A to the publisher account and its organization/robot; set B to the other account and its organization/robot. Match runner labels and stack bindings. Set the API URL for this build and a registry prefix both sides can use. Save environment.
  5. Run Preflight first, then start a new All campaign. Preflight checks the actual logged-in accounts, membership, robot ownership and readiness. Fix any pending prerequisites before running Live or All. After changing IDs or memberships, start a new campaign: existing campaigns keep their original targets and results.
  6. Add extra roles when you need their coverage. C is a third robot in A’s organization and may use A’s runner. Operator is another account with Operator membership in A’s organization. A’s owner can create an Operator invitation code under Organizations → Invitations; the new account pastes it into Join organization. No email service is needed. Without them, those cases stay pending. Official publishing needs the configured official publisher; hosted/browser and other operator checks need recorded evidence.
